   - Go: Parameterized queries generated by `sqlc` with `pgx/v5` driver (`$1, $2, ...`), verified zero string interpolation or `fmt.Sprintf` query formatting.
   - JS/TS: Client-side HTTP services use strictly typed JSON request payloads without raw SQL exposure.
2. **Secret & Credential Management**:
   - Zero hardcoded production passwords, JWT keys, or API tokens in source code.
   - All sensitive credentials sourced strictly via environment variables (`JWT_SECRET`, `POSTGRES_PASSWORD`, `RESEND_API_KEY`).
   - Mock dev mailbox utilized for local offline email inspections without external credentials.
3. **Command Injection**:
   - Zero unvalidated `os.system` or `child_process.exec` calls. All background tasks and workers invoke deterministic binaries.

## 4. Code-Enforced Autonomy Policy Engine

Model proposals are treated as untrusted suggestions. Permission boundaries are enforced deterministically by code outside the model (`authorize-action` evaluating `on-call-engineer/autonomy-policy.json`):

```
                       ┌────────────────────────┐
                       │ Firing Prometheus Alert│
                       └───────────┬────────────┘
                                   │
                                   ▼
                    ┌──────────────────────────────┐
                    │ Bounded Evidence Assembly    │
                    │ (collect-evidence: read-only)│
                    └──────────────┬───────────────┘
                                   │
                                   ▼
                    ┌──────────────────────────────┐
                    │ AI Model Root Cause Proposal │
                    └──────────────┬───────────────┘
                                   │
                                   ▼
              ┌──────────────────────────────────────────┐
              │ Code-Enforced Autonomy Policy Engine     │
              │ (authorize-action autonomy-policy.json)  │
              └────┬─────────────────┬─────────────────┬─┘
                   │                 │                 │
     Level 1: Safe │   Level 2: Code │   Level 3: Risk │
      Auto-Execute │  Human Approval │   Block/Escalate│
                   ▼                 ▼                 ▼
          [kubectl undo]      [git apply]       [FORBIDDEN]
          [compose up -d]     [Human Sign-off]  [Alert Team]
```

### Autonomy Tiering Matrix
| Autonomy Level | Permitted Operations | Human Gatekeeping | Execution Policy |
| :--- | :--- | :---: | :--- |
| **LEVEL 1: AUTO EXECUTE** | `kubectl rollout undo deployment/backend`<br>`docker compose -f docker-compose.deploy.yml up -d`<br>`docker compose restart <service>` | No | Executed automatically; strictly reversible; max 1 rollback / 2 restarts per incident. |
| **LEVEL 2: HUMAN APPROVAL** | `git apply /tmp/patch.diff`<br>`git cherry-pick <commit>`<br>`kubectl scale deployment/<service>` | Yes | Blocked pending explicit human review and cryptographic sign-off. |
| **LEVEL 3: ESCALATE** | Unallowlisted commands, cluster configuration mutations, credential alterations | Immediate Block | Terminated immediately with high-priority escalation. |

### Enforced Prohibited Patterns
The policy engine scans commands against forbidden patterns before evaluation. Any presence results in immediate rejection:
- `rm -rf`
- `DROP TABLE` / `DROP DATABASE`
- `TRUNCATE`
- `DELETE FROM ... WHERE 1=1`
- `gcloud projects delete`
- `kubectl delete namespace`
- `docker compose down -v`

## 5. Closed-Loop Resilience Drill Verification

The resilience loop was exercised through an intentional fault injection drill:

### Step-by-Step Drill Execution
1. **Fault Injection**:
   - Command: `bash on-call-engineer/scripts/inject-fault 500-burst --run-drill`
   - Trigger: Simulated burst of HTTP 500 requests against `/api` endpoints simulating downstream failure.
2. **Detection & Normalization**:
   - Prometheus alert `HighHttpErrorRate` breached threshold (`http_requests_total{status=~"5.."}`).
   - Webhook delivered to receiver (`receiver.go` on port 5050).
   - Normalized into `on-call-engineer/incidents/inc-*.json` conforming to `NormalizedAlertIncidentPayload` schema.
3. **Bounded Evidence Assembly**:
   - `collect-evidence` assembled evidence packet `on-call-engineer/evidence.json` capturing git commit history, 5xx status, container health, and Loki logs without exposing database secrets.
4. **Action Proposal & Policy Authorization**:
   - Proposed Action: `rollback` (Confidence: `high`, Rationale: `High 5xx rate detected after deployment`).
   - Policy Engine: Evaluated proposal against `autonomy-policy.json`.
   - Classification: `LEVEL_1_AUTO_EXECUTE` -> Approved for automated execution.
5. **Recovery Verification**:
   - Executed authorized rollback/restart command template.
   - Full 8/8 verification suite (`on-call-engineer/scripts/verify`) executed:
     - Check 1: 12 on-call artifacts present
     - Check 2: Prometheus alert rules syntax verified
     - Check 3: JSON schema validation passed
     - Check 4: Autonomy policy structure validated
     - Check 5: Synthetic incident triggered
     - Check 6: Incident persistence verified
     - Check 7: Bounded read-only evidence collection passed
     - Check 8: Policy engine Level 1 authorization & forbidden pattern blocking verified
